# Stage 08.6 — UI Polish v2

Status: **Complete** (2026-10-05). Folder covers, video double-click full screen, copying pictures and additive
selection are implemented, tested and measured end to end. The stage was closed with these items so the platform and
commander work (P01, C00) could start; further polish goes into a new viewer stage (12).

## Objective

Make browsing feel richer without costing anything on the scrolling surface. The first item: a folder tile shows
pictures from inside the folder instead of a plain folder symbol.

## Decisions applied

- **ADR-0024** (new): folder covers come from a shallow, bounded read of each visible folder. They are not indexed and
  share the preview cache.
- ADR-0003 / CACHE-DESIGN.md: cover previews use the normal cache keys and profiles.
- ADR-0015: the folder is not indexed. Hidden entries and links are skipped, as in scans.
- ADR-0014: no motion on tiles. The mosaic is static.

### Folder covers

- A folder tile with media shows one cover filling the box, or a 2×2 mosaic for 2–4 covers. A small folder badge in the
  corner keeps it recognisable as a folder. Folders without media, or that can't be read, keep the folder symbol.
- Only the **first 4** media files are looked at. Go reads the folder in chunks of 256 entries and stops at 4 media
  files or after 2,048 entries. It never lists the full folder, indexes it, or makes previews for its other files.
- Videos count only when ffmpeg is available (posters, ADR-0018). Hidden files, links and subfolders are skipped. The 4
  files are shown in natural name order.
- Covers are requested only for folder tiles that are visible or in overscan, never for the forward prefetch buffer.
  One `folder.covers` call goes out per settled range, and folders already known are not asked for again.
- Generation goes through the existing preview scheduler, on its own `covers` lane. It is bounded, deduplicated, and
  cancelled by epoch. Folder reads run on at most 4 goroutines per request. Results arrive batched on the
  `folder.covers` event.
- Cache keys are the same as for an opened folder's tiles (path key, size, mtime, profile). Opening the folder
  afterwards gets those 4 files as cache hits.
- What Go found is remembered per folder until the folder's mtime changes (at most 2,048 folders).

### Video double-click

- Double-click on a video tile selects it, shows the preview pane and asks the player for full screen with the click's
  user activation, before the media URL arrives. Playback starts once the URL is known. If full screen is refused, it
  plays in the pane. Esc leaves full screen and playback continues in the pane. Enter still plays in the pane.
- `previewStore.play` carries `fullscreen`; `VideoPlayer` takes `playFullscreen`.

### Copying pictures

- Ctrl/Cmd+C with one image selected does two things. It fills the internal file clipboard (unchanged, so Ctrl+V in
  Panelyth copies the file), and it puts the picture on the OS clipboard. With several items selected, only files are
  copied. In the viewer, Ctrl/Cmd+C (`viewer.copy`, remappable), a toolbar button and the right-click menu copy the
  shown picture.
- Go (`clipboard.image`, main only) decodes the original with the existing decoders, applies EXIF orientation, caps it
  at 40 MP and writes a PNG (fast compression, transparency kept) to `<cache>/tmp`. It shares the preview decode
  budget, runs one copy at a time, and removes leftovers at startup. Main reads the file asynchronously, passes the
  bytes to Electron 44's `clipboard.write([new ClipboardItem({ "image/png": blob })])` and deletes the file. No pixels
  travel over IPC, and nothing is decoded in main or the renderer.
- Renderer messages: "Picture copied to the clipboard", or "Couldn't copy the picture: …". "Copying picture…" shows only
  after 200 ms. Repeated Ctrl+C while one copy is running joins that copy.
- Context menus. Tile: Play / Play full screen (video), Copy picture (one image), Copy name, and Copy now does what
  Ctrl+C does. Viewer: Copy picture, Copy path, Open with default app, Show in file manager, Rotate left/right, Flip,
  Back to folder.

### Selection

- Shift+click and Shift+arrows select `base` + anchor..target. `base` is the selection when the anchor was last set
  (by a click, Ctrl+click, Ctrl+Space, a marquee, or a press on a selected tile). Earlier Ctrl+click picks therefore stay
  selected, and moving the Shift end replaces only the Shift range. A plain click empties `base`, so Shift then works
  as usual. Before this, Shift+click cleared the Ctrl picks, which users reported as losing their selection.
- Ctrl/Cmd+Shift+click and Ctrl/Cmd+Shift+arrows add anchor..target to everything currently selected. Before this, the
  keyboard path replaced the selection. A range also re-selects items that Ctrl+click had removed from it.
- Pressing on a tile inside a multi-selection keeps the selection for dragging. Releasing without a drag or marquee
  now selects only that tile. Before this, the selection stayed, so Alt+Enter or F2 acted on the whole group.

## APIs/contracts

- `folder.covers` (renderer → sidecar): `{ lane, epoch, profile, items: { id, priority }[] }`, at most 200 folders.
  It returns `{ items: { dirId, slots }[] }`. A slot is a `Thumb`, `{ failed }` or `{ pending: true }`.
- `folder.covers` event: `{ items: { dirId, slot, profile, url|failed, … }[] }`, coalesced (≤ 500 per event).
- Main validates the parameters, and the contracts have result and event guards. The golden fixtures are
  `res-folder.covers.json` and `evt-folder.covers.json`.
- `clipboard.copyImage` (renderer → main): `{ entryId }` → `{ width, height }`. Main calls the sidecar's
  `clipboard.image` (`{ entryId }` → `{ file, width, height }`, main only, with a result guard).

## Benchmarks

`go test ./internal/preview -bench FindCoverSources -benchmem` on an i9-13900K, a 10k-file folder, warm OS cache
(`shared/bench/results/stage-08.6-2026-10-05-covers-bench.txt`):

| Case | Time/op | Allocs/op |
|---|---|---|
| media near the start (stops after 4) | 0.09–0.16 ms | 697 |
| no media (bounded at 2,048 entries) | 0.95–1.0 ms | 6,220 |

An earlier run on the same machine measured 0.5–0.6 ms for the no-media case; the two runs differ by about 2×. Cold
network drives will be slower. This runs in the sidecar, off the UI thread, and never blocks scrolling.

### Tile scroll e2e (folder-heavy)

The fixture is 2,000 subfolders, each with six real 1600×1200 images hard-linked from one set. Every 5th folder has
only a text file. It is opened at 1920 px with medium tiles, flung for 3 s at 400 px/frame, scrolled slowly for 2 s,
and then returned to the top. Three runs on the i9-13900K
(`shared/bench/results/stage-08.6-2026-10-05-e2e-tiles.jsonl`):

| Metric | Result | Bound |
|---|---|---|
| mounted tiles (max) | 80 | ≤ 300 |
| long tasks | 0 | none ≥ 50 ms |
| p95 frame / max frame gap | 7 ms / 7–14 ms | — |
| `folder.covers` calls during the scroll | 1 | ≤ 10 |
| `folder.covers` calls on returning to the top | 0 | 0 |
| `preview.ensure` calls | 0 | 0 |

The test also checks that the first folder shows a 4-cover mosaic and that a folder without media keeps the folder
symbol. The 8 existing Stage 03 tile tests were re-run at the same time and all pass, with unchanged numbers (100k
scroll: 80/204 mounted tiles, no long tasks, 1 ensure call).

### Copying pictures and video double-click

`go test ./internal/app -bench ClipboardImage -benchmem`, i9-13900K, a 24 MP (6000×4000) JPEG
(`shared/bench/results/stage-08.6-2026-10-05-clipboard-bench.txt`): 353–362 ms/op, 133 MB/op (YCbCr decode + RGBA copy),
about 46 allocs/op. This runs in the sidecar under the shared decode budget. The UI shows "Copying picture…" after
200 ms and stays responsive.

E2E (`shared/bench/results/stage-08.6-2026-10-05-e2e-polish.jsonl`, `stage-06-2026-10-05-e2e-media.jsonl`), 3 runs each:
Ctrl+C on a 1600×1200 JPEG reaches the clipboard in 116–123 ms with no long tasks. Double-click on a video tile is
full screen and playing in 49–229 ms (the first run was a cold start).

## Acceptance criteria

- A folder containing pictures or videos shows up to 4 of them on its tile. An empty folder shows the folder symbol.
- Opening a parent folder never generates previews beyond 4 per visible folder.
- Scrolling past folder tiles issues no per-tile IPC and does not repeat requests for known folders.
- Opening a folder after seeing its covers reuses the cached cover previews.

## Risks and follow-ups

- Covers are not refreshed while the parent stays open. A change inside a subfolder shows after re-navigation, when
  the Go memo sees the new folder mtime.
- On Linux ext4 the directory order is hash order, so the 4 files are "first found", not the alphabetically first.
- The mosaic uses the tile profile for each quarter cell. That is more pixels than needed, but it lets an opened
  folder reuse the cache.
- Pre-existing, not from this stage: two `AppShell` theme-label tests and the two `theme.spec.ts` e2e tests fail
  ("Theme: Dark" vs "dark"), and ESLint reports `no-useless-assignment` in `SettingsDialog.tsx:281` (Stage 08.5).
  `tiles.spec.ts` "wider windows fit more tiles" depends on where the window lands on a multi-monitor desktop and failed
  twice today and passed when run again.
- A copied picture is a PNG. A 24 MP photo can make a 40–70 MB PNG at fast compression, which main reads and hands to
  Chromium's clipboard. The OS clipboard then holds its own copy. Electron 44 has no file-list clipboard format, so
  pasting into Explorer/Finder pastes a picture, not the file.
- Windows Storage Sense ("delete temporary files") empties the e2e fixtures in `%TEMP%/panelyth-fixtures`. Their
  files carry an old fixed mtime, and the marker files survive, so `ensureFixture` does not rebuild them. Delete the
  folder when large-folder tests suddenly find no tiles.
- The e2e helper `findTile` (`media.spec.ts`) now waits for the search to commit. Before this, it could click a tile
  that was already visible, and the search then reset the selection.
