# Testing Strategy (shared)

Test layers, harness, fixtures and benchmark rules for every app of the product family (ADR-0025). App-specific
scenarios and fixtures: `docs/viewer/TESTING.md`, `docs/commander/TESTING.md`.

## Unit tests

### React

Test:

- virtual range -> visible items
- page loading
- infinite scroll threshold
- keyboard navigation
- selection
- error placeholders
- theme state (dark default, cycling, persistence)
- design tokens: neutral grays and WCAG AA contrast, parsed from the real CSS (`src/styles/tokens.test.ts`)

### Go

Test:

- path normalization
- image type detection
- source identity
- cache key generation
- cache hit/miss
- request coalescing
- cancellation
- scanner filtering
- SQLite queries
- atomic cache write behavior

## Integration tests

### Go

- scan a generated fixture tree
- index many images
- query deterministic pages
- generate thumbnails
- reopen and hit cache

### Electron

- start sidecar
- open folder
- fetch first page
- request visible previews
- shutdown/restart sidecar cleanly

## End-to-end

Each app keeps its own scenario list: `docs/viewer/TESTING.md` and `docs/commander/TESTING.md`; the switch between
them is tested per `docs/shared/APP-SWITCHING.md`. Both apps share the harness (`src/shared/e2e/launch.ts`; Stage P01 adds
`launchApp({ app })` for the app shown at start, and access to each app view's page), the fixtures and the rules
below.

### Layout in jsdom

jsdom has no layout. Renderer tests that mount the tile view call `mockViewport(width, height)` (`src/test/viewport.ts`),
which fakes `getBoundingClientRect` (read by the tile view) and `offsetWidth`/`offsetHeight` (read by TanStack Virtual).
Real geometry, scrolling and frame timing are covered by the Electron e2e tests (`src/shared/e2e/specs/viewer/tiles.spec.ts`).

### Isolation

Every Electron launch, of either app, in e2e and benchmarks gets fresh `PANELYTH_CACHE_DIR`, `PANELYTH_CONFIG_DIR` and
`PANELYTH_USER_DATA_DIR` directories, so stored preferences, caches and logs never leak between runs. The
profile override is honoured only in unpackaged builds. `PANELYTH_TEST_SHELL=record` (set by `launchApp`) makes main
record "open with default app", "show in file manager", clipboard writes and the commander's commands
(`shell.run`, `shell.runTool`: the program, its arguments, the folder and the added environment) in
`__panelythShellLog` instead of performing them.

Radix triggers in jsdom: with `mockViewport` every element has the same rectangle, so react-resizable-panels treats
each pointerdown as a divider drag and prevents it. App-shell tests open dropdowns from the keyboard and type into
already focused inputs (`skipClick`). Pointer behavior is covered by the Electron e2e tests.

## Performance fixtures

Generated by `src/shared/sidecar/cmd/fixturegen` (shared by Go tests, `pnpm bench:index` and e2e), cached per machine
under `<tmp>/panelyth-fixtures/<name>` with a marker file: `flat-100k` (90k media + 10k non-media), `tree-50k`
(depth 3 × fanout 6, 46,620 media), `flat-5k`, and real images: `images-150` (1600×1200, PNG-with-alpha and
EXIF-rotated variants; e2e) and `images-12mp-120` (4000×3000; `pnpm bench:previews`, viewer e2e), `images-48mp-3` (8000×6000; large-decode e2e), `tree-small` (navigation e2e) and `subdirs-10k` (a folder with 10,000
subfolders for the lazy tree; created by the e2e spec). Mtimes are fixed, so query
results are deterministic.

Windows Storage Sense ("delete temporary files") can empty these folders: fixture files carry fixed, old mtimes, and
the marker files survive, so `ensureFixture` does not rebuild them. When large-folder tests suddenly find no tiles or
rows, delete `<tmp>/panelyth-fixtures` and run again (seen on 2026-10-05).

Keep deterministic fixture sets for:

- small folder
- large folder
- huge folder
- mixed unsupported files
- repeated filenames
- rapidly changing files

## Benchmarks

Track:

- files/sec scan
- metadata/sec
- SQLite page latency
- JPEG decode + resize latency
- cache hit latency
- cache miss end-to-end latency
- renderer frame/scroll behavior
- image editor: session open, a dragged control's render latency, save, heap per session (`pnpm bench:edit`, Stage 12);
  the color tools' drags, full frames, probe, thumbnails, color count and saves (the `color` block, Stage 13;
  `BENCH_LARGE=1 go test ./internal/imaging -bench ColorTools` for the single passes); the effects
  (`-bench Effects`, Stage 14); strokes, clone, heal and red-eye (`-bench DrawAndRetouch`, Stage 15); a batch
  through the real service: throughput per worker count, peak heap, cancel, the plan of 100,000 pictures and
  thumbnails beside a batch (`PANELYTH_BENCH_BATCH=1 go test ./internal/app -run TestBenchBatch`, Stage 16)

Do not rely only on synthetic microbenchmarks. Include a real end-to-end benchmark path.
