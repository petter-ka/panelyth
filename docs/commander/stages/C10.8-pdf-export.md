# Stage C10.8 — PDF Export

Status: **Implementation done** (2026-10-24, Windows; planned 2026-10-23, owner request: in the first release).
Track: commander. Depends on: C10.7. Unblocks: C11. Open: the macOS and Linux runs, the NVDA pass.

## Objective

Export a clean PDF of a Markdown document (or of any text file, as its source with syntax colors).

## Decisions applied

- ADR-0046: `webContents.printToPDF` of the editor's own page; the document rendered from the same lezer tree as
  the live view and cleaned by DOMPurify; main writes the PDF where its save dialog says, asynchronously and
  atomically.

## Scope

- File → Export PDF (Ctrl+Shift+E): page size (A4, Letter), margins, light page colors whatever the theme, page
  numbers in the footer; headings, code blocks, tables and linked pictures as in the live view; page breaks avoid
  splitting code blocks, tables and pictures where they fit on one page.
- The export runs off the keystroke path; a large document shows progress and can be cancelled.

## Non-goals

- A table of contents, headers with the title, custom stylesheets, other formats (HTML, DOCX).

## Implementation tasks

1. The print stylesheet over Preview's rendering (C10.7: HTML from the tree, DOMPurify).
2. Main: `editor.exportPdf` (the save dialog in main, `printToPDF`, an atomic asynchronous write).
3. The pictures it links are resolved through the C10.7 batch before printing.

## APIs/contracts

- `editor.exportPdf { pageSize, margins }` → `{ path | null }` (null when the dialog was cancelled).

## Tests

- The print stylesheet's page breaks for a corpus (code blocks, tables and pictures kept whole where they fit);
  E2E: export with a canned save path, the PDF exists, has the pages and the text.

## Benchmarks

`BENCH_STAGE=C10.8`; exporting a 100-page document ≤ 5 s; the editor stays responsive during the export.

## Acceptance criteria

- A README with code, tables and pictures exports to a PDF that reads like the live view on white paper.

## Risks

- Page breaks inside long code blocks: allowed when the block is longer than a page.

## Results (2026-10-24, Windows, i9-13900K)

**Built.**

- **The command:** "Export PDF" in the editor's header, for every file type and in read-only windows too, and
  Ctrl+Shift+E. A dialog asks for the page size (A4 or Letter; Letter by default in the US) and the margins
  (narrow, normal, wide); the last choice is remembered.
- **The print view:** laid out by the page, only while an export runs, and shown only under `@media print`.
  - Markdown: Preview's rendering (the same serializer and DOMPurify rules, now shared in `markdown/sanitize.ts`),
    with every picture resolved first and loaded (at most 10 s).
  - Other text: the source with line numbers and the editor's own syntax colours.
  - The print stylesheet: black on white whatever the theme; the bundled Inter font, so a PDF lays out alike on
    every OS; code blocks, tables, pictures and quotes kept whole where they fit; web links' URLs printed after
    them; task boxes as ☐/☑; no ligatures in code.
- **Saving:** main's save dialog names the file, starting beside the document under its name. Main prints the
  editor's page (`printToPDF`, a page-number footer) and writes the PDF whole (a partial file, then a rename).
  The page learns only the file's name.
- **Cancelling:** possible while the print view is being built (Esc, or Cancel in the status bar). Once main is
  printing it can't be cancelled; that step takes about a second for 100 pages.

**Tests.**

- Main: the dialog's default path, the print options (margins in inches, size, footer), the write, a cancelled
  dialog printing and writing nothing, and the validator refusing other sizes, margins or a path.
- Page: 182 unit tests, covering the print view's HTML (unsafe HTML harmless), pictures resolved in batches, the
  JSON source view, the dialog's defaults and memory, and the flow (success, cancel, error, one export at a time).
- E2E, read back with pdf.js:
  - a Markdown report exports to a PDF holding its heading, code, table, the link's URL and the picture, and the
    print view is gone afterwards;
  - 101 pages export within the budget.

**Measured** (results `stage-C10.8-2026-10-24-*`):

| Metric | Budget | Measured |
|---|---|---|
| Export of 101 A4 pages (Export clicked → saved) | ≤ 5 s | 1.16–1.17 s (2 runs) |
| Print view of 1 MB Markdown with 200 pictures (headless Chromium harness) | the editor stays responsive | 1.74–1.79 s to build; frames p95 18 ms, longest 20 ms |
| The editor's bundle | recorded | +4 kB in the main chunk (the dialog); the export is a 2.8 kB lazy chunk that shares DOMPurify with Preview |

**Noted:** opening a dialog in the editor logs one CSP message about an inline style: Radix's scroll lock, which
the commander's dialogs also hit. Nothing breaks, and no violation event fires.
