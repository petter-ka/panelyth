# Stage C10.5 — Tab Sets, Folder Tree, FTP Connections and Compare Selected Files

Status: **Implementation done** (2026-10-12, the day of the owner's request; Windows). Open: the owner's
confirmation that FTP is on in the first release, the Linux and macOS runs, the NVDA pass (see "Results"). Track:
commander. Depends on: C10 (C03 for tabs, C04 and P03 for transfers, C07 for the session-source pattern, C08 for
compare). Unblocks: C11.

## Objective

Four additions the owner asked for before the commander's release:

- tabs that can be added, closed and **saved** from the tab bar itself, not only by key;
- a **folder tree** beside the panels;
- **FTP**: connect to a server, browse it in a panel, transfer files, and save connections;
- **compare the selected files**, for any number of them.

Two of the four extend what exists. Folder tabs were built in Stage C03 (Ctrl+T, Ctrl+W, reorder, lock, restored
with the session) and Compare by content in Stage C08 (two files). This stage adds what they lack; it does not
rebuild them.

## What exists and what this stage adds

| Request | Exists | Added here |
|---|---|---|
| Tabs: add, remove, save | C03: Ctrl+T, Ctrl+W, middle-click, × on hover, drag to reorder, lock, close others; tabs persist in `commander.panels`. The tab bar is hidden while a panel has one tab, and there is no "+" button | the tab bar always shown with a **+** button; rename, duplicate, reopen closed tab; **saved tab sets** |
| Tree view | the viewer's lazy folder tree (`src/viewer/renderer/src/features/tree`); nothing in the commander | a tree pane for the commander on the same code, moved to `src/shared/` |
| FTP, connections, saving | nothing; out of scope in the BRS until now | remote locations over FTP and FTPS, a connection manager, saved connections (ADR-0037) |
| Compare selected files | C08: two files, as a text diff or "identical / different" | several files at once with a result list; Total Commander's pairing rule; changes marked inside a line |

## Decisions applied

- **ADR-0037 (accepted with amendments in this stage):** remote locations. FTP and FTPS folders are a
  query-session source, connections are saved in `library.db`, passwords are encrypted by Electron main, transfers
  are jobs.
- ADR-0017 (session sources; amended again for the remote source), ADR-0029 (jobs, lanes; a lane per connection),
  ADR-0027 (the commander's profile only; ids, not paths), ADR-0028 (virtualized lists, fixed row heights), ADR-0016
  (connections and tab sets are durable user data), ADR-0019 (no cgo: the FTP client is pure Go), ADR-0034 (every new
  message in all languages).

## Scope

### 1. Tabs

- The tab bar is always shown (Settings → Panels → "Show the tab bar": always, or only with several tabs as today),
  with a **+** button at its end. The × is always visible on the active tab, on hover on the others.
- New commands in the tab menu and the keymap: **Rename tab** (a title that replaces the folder name; empty restores
  it), **Duplicate tab**, **Reopen closed tab** (Ctrl+Shift+T; the last 10 per panel, kept in memory only), **Close
  tabs to the right**.
- **Saved tab sets:** "Save tabs…" stores the panel's tabs (or both panels') under a name; "Open tab set" lists the
  saved sets and opens one, replacing the panel's tabs or adding to them; "Manage tab sets…" renames and removes them.
  A set stores what a tab stores in the session: folder, title, sort, view, hidden files, lock. Tabs on archives, find
  results and connections are saved as their folder, as their archive file's folder, or left out; the dialog says how
  many were left out.
- Opening a set opens **one** session, the visible tab's. The other tabs stay records until shown (ADR-0028).
- A locked tab still cannot be closed by × or Ctrl+W; opening a set with "replace" asks first when a locked tab would
  go.

### 2. Folder tree

- **Tree pane (Ctrl+Shift+F8 cycles):** off → one tree left of the panels that follows the active panel → a tree
  beside each panel → off. Width resizable by a divider and persisted (`commander.layout`).
- Roots: the drives and places of the drive menu. A node lists its subfolders when it is expanded, one level at a
  time, never recursively (`fs.listDirs`). It honors the panel's hidden-files setting.
- The tree follows the panel: after a folder change it expands the path and puts its highlight there. That runs
  after the panel's first rows are painted and never delays them (performance invariant 1).
- Keys in the tree: ↑ ↓ PgUp PgDn Home End move; → expands or goes to the first child; ← collapses or goes to the
  parent; Enter opens the folder in the panel and returns the keys to it; letters jump to the next visible node by
  name; Tab or Esc return to the panel; Ctrl+R re-lists the node. Shift+Tab from a panel moves into its tree.
- Moving the tree's cursor does **not** change the panel by default (Settings → Panels → "The tree opens folders as
  the cursor moves", with a 150 ms settle as the quick view has).
- Mouse: click opens the folder in the panel; the arrow expands; a node is a drop target for panel items with the
  copy dialog (Shift: move), like a tab or a drive button. The menu of a node: open in the left or the right panel,
  open in a new tab, new folder, add to the hotlist, refresh.
- Rows are virtualized with `@tanstack/react-virtual`, with the panel's row height. Nodes live outside React state;
  a node that reports more subfolders than the listing's cap shows "… more" (the viewer's `truncated`).
- A panel inside an archive, on find results or on a connection keeps the tree on the last local folder, dimmed.
- The tree and its store move from the viewer to `src/shared/renderer-core` (store, as a factory: the commander needs
  up to two) and `src/shared/ui` (rows); the viewer's sidebar uses them from there. No copy stays in either app.

### 3. FTP connections (ADR-0037)

- **Protocols:** FTP and FTPS (explicit TLS, the default for a new connection, and implicit TLS). Passive mode by
  default; active mode as a per-connection option.
- **Connections (Ctrl+F):** a list of saved connections with Connect, New, Edit, Duplicate, Delete and groups. A
  connection: name, host, port, encryption, user or anonymous, password (saved, or asked every time), the folder on
  the server to start in, a local folder for the other panel (optional), passive or active, the encoding of names
  (UTF-8, or a chosen code page for old servers), simultaneous transfers (1–4).
- **Quick connect (Ctrl+N):** host, user and password without saving; "Save this connection" afterwards.
- **Saving:** connections are rows in `library.db`. A password is encrypted in Electron main (`safeStorage`: DPAPI,
  Keychain, libsecret) and stored as ciphertext; it never returns to a renderer. Where the OS offers no secure store,
  passwords are not saved and the dialog says so.
- **Browsing:** a connected server is a panel location. Folders list through MLSD (LIST parsed where MLSD is
  missing), are sorted and paged in Go like any listing, and work with the cursor, marks, quick search, quick filter,
  sorting, tabs and history. The path bar shows `ftp://user@host/path` with a lock glyph for TLS; the drive bar shows
  the connection as a button with **Disconnect** (Ctrl+Shift+F). There is no watching: Ctrl+R re-lists, and so does
  every job of the app that changed the folder.
- **Transfers:** F5 and F6 between a connection and a local folder are `download` and `upload` jobs in the queue
  (ADR-0029): a lane per connection, progress, speed, ETA, pause, cancel, the conflict policies by size and date, and
  resume of a partial file where the server supports it. Drag and drop and the internal clipboard do the same.
- **On the server:** new folder (F7), rename (Shift+F6, F2), delete (F8). There is no trash on a server: the delete
  dialog says so and is the permanent-delete dialog.
- **Viewing:** F3, quick view and Enter on a file download that one file to `<cache>/tmp/remote/` (bounded, as for
  archives) and show it from there.
- **Trust:** plain FTP shows "Not encrypted: the password and the files can be read on the way" in the connection
  dialog and a marker in the path bar. A connection set to TLS never falls back to plain FTP. A certificate that does
  not verify is shown with its fingerprint; the user accepts it once or for the connection.
- **Lifetime:** nothing connects without a command. A restored tab on a connection shows "Not connected" with a
  Connect button; startup opens no connection. An idle connection is kept alive while a panel shows it and closed
  after 5 minutes without a panel, a parked tab or a job; the next action reconnects. Jobs keep their connections
  while the commander is hidden.
- **States (CFR-28):** connecting (with Cancel), wrong user or password, host not found, timed out, connection lost
  (Reconnect), refused by the server (its message shown), not supported here.

### 4. Compare selected files

- **Pairs (extends C08's rule):** one file marked in each panel → those two (Total Commander's rule); two marked in
  the active panel → those two; nothing marked → the cursor file against the file of that name in the other panel,
  else against that panel's cursor file.
- **Several files:** more than two marked files are each compared with the file of the same name in the other
  panel, as **one** `compareFiles` job (files only: a marked folder is left out and counted). The result is a list:
  identical, different, differ only in line ends or encoding, missing on the other side, could not be read; with
  counts per kind and filters. Enter on a "different" row opens the text diff of that pair; N / P in the diff step to
  the next and previous differing pair.
- **Inside a line:** in the text diff, the changed part of a changed line is marked on both sides (computed in Go for
  the rows of the page asked for; lines stay cut at 4 KiB).
- **Reach:** "Compare by content" joins the default toolbar. It keeps no default key (Total Commander has none) and
  can be bound. Its menu entry says what it will compare ("Compare 2 files", "Compare 14 files with the other
  panel").

## Non-goals

- SFTP, WebDAV and cloud storage (still out of scope; ADR-0037 leaves room for SFTP behind the same interface).
- Server to server copies between two connections, and editing a remote file in place (F4 with upload on save).
- On a connection: find files, branch view, folder sizes, synchronize directories, compare by content, checksums,
  pack and unpack, multi-rename, change attributes, the command line, thumbnails of pictures (type icons only), and
  the switch to the viewer carrying the folder. Each says "Not available on a connection" instead of doing nothing.
- Remote folders in the tree; Total Commander's Alt+F10 tree dialog; a tree inside a panel (Ctrl+F8).
- Tab sets as files to exchange between machines; tab groups and colors.
- Three-way compare, editing in the diff, comparing folders' files recursively (that is Synchronize, C08).

## APIs/contracts

Commander profile only; the viewer is refused every `remote.*` method and the three job kinds.

- **Tabs:** no new method. `commander.tabSets` `{ v: 1, sets: [{ id, name, left?: Tab[], right?: Tab[] }] }` (at
  most 50 sets of at most 32 tabs a panel); `commander.panels` v3 adds `title` to a tab (v2 is still read).
- **Tree:** `fs.listDirs({ path, showHidden })` for the commander; `commander.layout` gains `tree: "off" | "one" |
  "two"` and the tree widths.
- **Connections:** `remote.connections()` → the saved connections without secrets (`hasPassword`);
  `remote.saveConnection(connection, password?)` (the password is write-only: main encrypts it before the sidecar
  stores it); `remote.removeConnection(id)`; the `connections.changed` event.
- **Sessions:** `remote.connect({ connectionId } | { quick: { host, port, user, tls, … } }, password?)` →
  `{ remoteId, features, tls, startDirId }` or `details.reason` (`auth`, `host`, `timeout`, `tlsRequired`,
  `certificate` with the fingerprint); `remote.cancel`, `remote.disconnect({ remoteId })`,
  `remote.trust({ connectionId, fingerprint, remember })`; `remote.open({ remoteId, path })` → `{ remoteDirId }` (the
  remote counterpart of `dir.open`); `query.open { remoteId, remoteDirId }`; `remote.mkdir`, `remote.rename`; the
  `remote.state` event (connected, reconnecting, lost, closed).
- **Main only:** `remote.secret(connectionId)` returns the ciphertext to main for decryption; no renderer method
  returns a password in any form.
- **Jobs:** `download { source: descriptor of a remote session, destinationDirId, policy, … }`,
  `upload { source, remoteId, remoteDirId, policy, … }`, `remoteDelete { source }`; `compareFiles` gains
  `{ source: descriptor, otherDirId }` beside its pair form, with one item per file and the codes `DIFFERENT`,
  `NOT_FOUND`, `TEXT_EQUAL`.
- **Diff:** `diff.page` rows carry `spans` for changed lines: groups of four numbers, one per changed place, `[left
  from, left to, right from, right to]` in UTF-16 units. Go compares the line word by word (words, white space and
  single characters; a bounded table, one stretch above it) and narrows a word that became another word to the
  characters that differ. The dialog shows the two files in two panes that scroll together and marks each place in
  its own pane.
- Remote entry ids come from a range of their own (proposed: from 7·2^50 up, taken from the top of the compare
  range), so a descriptor over a remote session never resolves to a local file.

> As built: `commander.tabSets` is `{ v: 1, sets: [{ id, name, panels: [{ tabs, active }] }] }`; `commander.layout`
> is `{ v: 1, split, tree, treeWidth }`; a v3 tab may carry `remote { connectionId, label, host, port, user,
> encrypted, path }`. The connection methods as built are listed in `docs/shared/DOMAIN-API.md` ("Connections"):
> `remote.connect` returns `{ remoteId, host, port, user, encrypted, features, startPath, localPath }` and takes an
> `attempt` number that `remote.cancel` names; `remote.open` takes `path | dirId` and an optional `attempt`;
> `remote.trust` is `{ connectionId, fingerprint }`; `remote.secureStore` says whether passwords can be kept; there
> is no `remote.state` event. `upload` is `{ source, remoteDirId, conflict, move? }` and `download`
> `{ source, destinationDirId, conflict, move? }`. `compareFiles` over a selection is `{ source,
> destinationDirId }` with the codes `DIFFERENT` and `NOT_FOUND`. Remote ids are 7·2^50 … 2^53.

## Acceptance criteria

- The budgets under "Tree, tabs and connections" pass, and the earlier commander budgets and the viewer's stay
  within theirs.
- A tab can be added, renamed, closed and reopened by mouse alone and by keyboard alone; a saved set comes back
  after a restart with its folders, views, sorts and locks.
- The tree never mounts more than the visible rows plus overscan, and a folder enter is as fast with it as without.
- A server that hangs, at any point, never stalls the other panel, the command line or the queue; every remote
  action can be cancelled.
- No stored password is readable in `library.db`, in logs or from any renderer.
- A connection that requires TLS fails closed; a name sent by a server never makes a job write outside its target.
- Nothing connects at startup or without a command.
- The security review of the remote path is recorded in this document with no open blocking finding.

## Risks

- **Size.** FTP is most of this stage: a client, a session source, three job kinds and a security review. If it
  slips, tabs, the tree and compare can close as C10.5 and FTP moves to a stage of its own; the scope above is cut so
  that split costs nothing.
- **Server variety.** LIST output has no standard, clocks and time zones differ, some servers lack MLSD, REST or
  UTF-8. Mitigation: MLSD first, a tested set of LIST dialects, capabilities read with FEAT and shown per
  connection; dates from LIST are compared to the minute.
- **Clear-text FTP.** Mitigation: TLS is the default, plain FTP is labelled where the user decides and where they
  work, and nothing falls back silently.
- **Password storage on Linux** without a keyring. Mitigation: no saving there, said in the dialog; never a
  clear-text fallback.
- **Moving the tree** touches the viewer's sidebar. Mitigation: task 2 lands first, with the viewer's suite and
  budgets as the gate.
- **Dead connections** behind a NAT that drops idle control connections during a long transfer. Mitigation: keep-alive
  on the control connection, one retry with resume, then a per-item failure.

## Open points for ADR-0037 (settled at the start of the stage)

- The FTP library (candidate: `github.com/jlaffaye/ftp`, pure Go, ISC) or a client of our own; its license goes to
  the notices (Stage P06).
- Whether `safeStorage`'s `basic_text` backend on Linux counts as "no secure store" (proposed: yes).
- The id range of remote entries.
- Whether FTP ships in the first release or behind a setting until C11's cross-platform pass.

### Deviations from the plan

Tabs:

- "Open tab set" and "Manage tab sets…" are one dialog, **Tab sets…**: open in place of the tabs or after them,
  rename, remove.
- A set is stored as `{ id, name, panels: [{ tabs, active }] }` (one panel, or left and right), not `left?` /
  `right?`. A one-panel set opens in the active panel.
- A tab on a connection is saved in a set as its folder of this computer.

Folder tree:

- Roots are the drives. The places of the drive menu are not roots.
- The node menu has no "New folder" (F7 in the panel does it).
- The shared code is the store and the twisty; the rows stay per app (the viewer's carry its own menu and badges).
- The `tree-wide` fixture is written by the spec, not by `fixturegen`.

Compare:

- There is no `TEXT_EQUAL` result ("differ only in line ends or encoding"): a pair is identical, different or
  missing. Opening a different pair shows the text diff, which says so when only line ends differ.
- In the diff, **Shift+N / Shift+P** step to the next and previous differing pair (N and P are taken by the diff's
  own next and previous change).
- Rows of the result list are found in the panels by name.

FTP:

- **The client is our own** (ADR-0037 "Settled"); no library was added.
- **No keep-alive.** A socket closes after 5 minutes without a command and the next command opens it again. The
  plan's "kept alive while a panel shows it" would have kept sockets open behind an idle app; the risk "dead
  connections behind a NAT" is answered by the reconnect instead.
- **Uploads write to the final name**, and the size the server reports is checked afterwards (FTP has no portable
  rename-over). Downloads use a partial file as planned.
- **The file clipboard is not available on a connection** (the plan had it do transfers): its entries are shared
  with the viewer, which must never be handed an entry of a connection. Drag and drop works, and always shows the
  dialog.
- **The connection dialog** is a list with a form opened from it, not a list with the form beside it.
- **A lock glyph** became the word "FTPS" in the path bar, beside "Not encrypted" for plain FTP: two words read
  the same way by everyone, never an icon alone.
- **Enter on a file** of a server shows it (the media viewer, the lister, the document window). Nothing a server
  sends is started, edited or handed to a user command: the file has no path on this computer.
- **View copies** are capped at 256 MiB a file and 16 files a connection.
- **A listing can be stopped** (not in the plan's API): `remote.open` takes an `attempt` and `remote.cancel` ends
  it. Without it a server that stopped answering held a panel for the command timeout.
- **No `remote.state` event.** A command on a closed connection answers `closed`, and the panel shows "Not
  connected"; the idle close and reconnect need no state on screen.
- `remote.trust` takes `{ connectionId, fingerprint }` (no `remember`: trusting once is `accept` on the connect).
- New folder and rename on a server cannot be cancelled while they wait (up to the 30 s command timeout); their
  dialogs can be closed meanwhile and nothing else waits on them.
- The hotlist and user commands are in the "not available on a connection" list as well.
- Not built from the list of states: showing a connection's features (MLSD, resume) per connection.

Notes on the numbers:

- **Uploads and this computer's disk.** The first upload numbers were 0.12 and 0.33 times `curl`. The cause was not
  the client: the fixture server wrote each gigabyte to a disk that is 99 % full, and that disk stalls for seconds
  (once for 42 s) after a few GiB of writes; the stalls hit the app's runs and `curl`'s alike, in whatever order
  they came. Taken apart in Go against the same server process: our copy loop sends 2,600–2,700 MiB/s where `curl`
  sends 2,170–2,240 MiB/s, and handing the file to the socket (`TransmitFile`) is slower, at 1,800–1,900 MiB/s, so
  the loop stayed. The benchmark now uploads to a server that receives without writing (`-discard-uploads`), so the
  number is the app's sending. Against a server that writes to this disk, both take 0.8–2.6 s per GiB. A job has a
  fixed cost of about 60 ms (a 1 KiB upload; `curl`: 12–17 ms), which is why the whole-job ratio is lower than the
  ratio of the bytes alone (1.0–1.35).
- **Many small files** are slower than `curl` (one data connection per file on both sides; `curl` keeps one
  control connection, we use two transfer sockets and check each name). No budget; recorded.
- **One optimization, measured:** a listed entry kept its whole listing line alive through its name. Copying the
  name took a 100,000-entry folder from 126 to 78 bytes per entry (`TestMemoryPerListedEntry`).
- The 100k-folder enter with the tree shown was measured on the cached 1,000-entry folder, where the tree's cost
  would show most; a 100k run is in the C01 regression below.

### Security review of the remote path

Reviewed against ADR-0037 and the list in `docs/commander/TESTING.md`. No open blocking finding.

| Question | Answer | Evidence |
|---|---|---|
| Can a renderer read a password? | No. No method returns one; a typed one lives in its field and one call. | `test/remote.test.ts` (main); `remote.test.tsx`: the password is in no store and no setting |
| Is a stored password readable on disk? | No: ciphertext from `safeStorage` only. | E2E: after saving, the password is in no file of the profile (config, cache, logs, Electron data), in UTF-8 or UTF-16 |
| What if there is no secret store? | Nothing is saved; the user is asked each time. Linux `basic_text` and an unknown backend count as none. | main's tests; E2E with the store forced off |
| Is a password logged? | No log line carries `remote.*` parameters; a connect logs host, port and encryption. | the same E2E scan covers the logs |
| Can a TLS connection be downgraded? | No. A server without TLS is refused before USER and PASS. | Go `TestTLSIsNeverGivenUp`; E2E: the server saw no PASS |
| An unknown or changed certificate? | Refused with its fingerprint; accepted once or remembered by the user; a changed one is refused again and said to have changed. | Go, renderer and E2E (the fingerprint shown is the server's) |
| Can a server make the app connect elsewhere? | No: the address in a PASV reply is ignored; data goes to the control connection's host. | Go `TestPassiveAddressOfTheServerIsIgnored` |
| Can a name from a server leave its folder or start a command? | No: such names are not listed, and a download checks its target again. Names typed for a server are one line without separators. | Go `TestHostileNamesAreNotListed`, `TestDownloadNeverWritesOutsideItsFolder`; validators |
| Can the renderer hand over a path? | Only two typed inputs exist: a host and a path on the server, both checked in main. Local targets are folder ids. | `router.test.ts` |
| Is anything a server sends executed? | No. `entry.path` refuses entries of a connection, so nothing is started, revealed, edited or given to a command; a file is only shown, from a bounded temporary copy with a name of the app's own. | Go `TestRemoteJobsOverRPC`, `TestRemoteFileIsDownloadedToBeViewed`; `remote.test.tsx` |
| Can the viewer reach any of it? | No: every `remote.*` method, the three job kinds and `query.open` with `remoteId` are refused; the clipboard, which the viewer shares, refuses entries of a connection. | `router.test.ts`; Go |
| Does anything connect on its own? | No: not at startup, not on session restore, not when a tab is shown, not when the list of connections is read. | E2E: the server's session count is unchanged across a restart; `remote.test.tsx` |
| Can a server hang the app? | No: every dial, command and transfer has a timeout; a connect and a listing can be cancelled; the other panel stays at 7 ms a frame. | Go and E2E |
| Resource bounds? | 8 connections, 1–4 transfers each, 200,000 entries a folder and 1,048,575 a connection, 256 MiB and 16 files of view copies, a password of 1,024 bytes. | Go |

Accepted and written down (not blocking):

- Plain FTP sends the password in the clear. It is the user's choice per connection, said in the dialog and in the
  path bar.
- "Trust this time" for a certificate nobody vouches for is as safe as the fingerprint comparison the user makes.
- The clear password is in main's memory for one call and in the sidecar's for the life of a connection; a crash
  dump of either could hold it.
- A stored password is as safe as the OS account: anything running as the user can ask the secret store.
