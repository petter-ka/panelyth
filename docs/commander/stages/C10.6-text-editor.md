# Stage C10.6 — Text Editor: Window, Save, Find and Replace, Word Count

Status: **Implementation done** (2026-10-24, Windows; planned 2026-10-23, owner request: in the first release).
ADR-0046 accepted with amendments. Open: the Linux run of the Go suite (symlinks, Unix paths), the macOS and Linux
runs of the app, the NVDA pass, and Compare on a conflict (moved to later, see ADR-0046). Track: commander. Depends on: C10.5 (C05
for F4 and the lister, ADR-0033 for the document window's read path). Unblocks: C10.7, C10.8, C10.9, C11.

## Objective

Write notes, fix a README or change a config file right next to the files: a built-in editor for text, Markdown,
code and config files that opens from the commander, colors code, saves safely, and has find and replace and a
word count. ADR-0046 (proposed) is decided in this stage.

## Decisions applied

- ADR-0046 (this stage decides it): a window of its own with an `editor` origin and profile; sessions, not paths;
  bytes read through a read-only token; CodeMirror 6; atomic save with a conflict check; F4 opens it unless an
  external editor is set.
- ADR-0027 (profiles; the viewer never opens it), ADR-0033 (the document window stays read-only), ADR-0034 (its
  text is translated), ADR-0041 and ADR-0045 (appearance; the editor window keeps the native frame for now).
- `docs/commander/BRS.md` CFR-32.

## Scope

- **Opening:** F4 on a file opens it in the editor (unless Settings → Edit names an external editor); Shift+F4
  creates a file and opens it; "Edit" in the entry menu. One window per file: opening it again focuses its window.
  Text up to 8 MiB; a larger file or one that is not text (NUL bytes in the first 8 KiB) opens in the lister instead
  with a notice.
- **Editing:** CodeMirror 6 with line numbers, the current line, bracket matching, soft wrap (a toggle), undo and
  redo, multiple cursors, indentation by the file's own style, and syntax colors chosen by extension: Markdown,
  JSON, YAML, TOML, INI, XML/HTML, CSS, JavaScript/TypeScript, Python, Go, shell, SQL and plain text. Languages load
  on first use. The theme follows `shared.appearance`.
- **Saving:** Ctrl+S; the title shows a dot while there are unsaved changes; closing with changes asks Save, Don't
  save or Cancel. The file keeps its encoding (UTF-8 with or without BOM, UTF-16 LE/BE, Windows-1250/1252) and its
  line endings. A file changed on disk since it was opened is a conflict: Overwrite, Reload or Compare (the C08
  diff). The check also runs when the window regains focus.
- **Find and replace:** Ctrl+F and Ctrl+H; case, whole word and regular expression; replace one or all; the match
  count.
- **Word count:** words, characters and lines in the status bar; of the selection when there is one; computed off
  the keystroke path (debounced, in chunks for large documents).
- **Status bar:** line and column, encoding, line endings, language, word count.

## Non-goals

- The Markdown modes (Live, Preview and the switch between them and Source) and images (C10.7), PDF export (C10.8), files on servers (C10.9).
- Files inside archives, a project tree, tabs of several files in one window, Git in the editor, spell checking,
  language servers or completion.

## Implementation tasks

1. ADR-0046 accepted (with amendments found in the stage); ADR-0027, ADR-0033 and ADR-0044 amended.
2. **Sidecar** (`editor` service): `editor.open` (an entry id → size, modified time, SHA-256 version, encoding,
   line endings, text or not), `editor.write` (a chunk ≤ 256 KiB to a staging buffer, bounded per session to
   8 MiB), `editor.commit` (base version, force; encode, write a temporary file in the same folder, fsync, rename
   over the original; through links; keeps the file's mode and, on Windows, its attributes), `editor.check`
   (the version on disk now), `editor.close`. Sessions are cancelled with their window.
3. **Main:** `editorWindow.ts` (one window per entry, the `app://editor/` origin, its preload and profile, the
   session bound to the window, the read token, the close prompt); the methods checked against the window's
   session.
4. **Renderer** `src/shared/doceditor`: CodeMirror 6, language loading, find and replace panel, status bar, the
   save and conflict dialogs, word count, appearance sync, translations.
5. **Commander:** F4 and Shift+F4 routing (Settings → Edit: built-in or external), the entry menu's "Edit".
6. Budgets in `docs/commander/PERFORMANCE.md`; `pnpm bench:bundle` before and after.

## APIs/contracts

- Commander → main: `editor.openWindow { entryId }` (commander profile).
- Editor window → main → sidecar (the `editor` profile; every call names only its session):
  `editor.session` (the session's file name, size, encoding, line endings, version and read token),
  `editor.write { seq, text }`, `editor.commit { baseVersion, force? }`, `editor.check`, `editor.compare`
  (opens the C08 diff in the commander), `editor.closed`.
- Events: `editor.state` (saved, conflict) to the editor window.

## Tests

- Go: open, encodings and line endings round trip byte for byte, the atomic write (a failed write leaves the
  original), the conflict, links, a read-only file, chunk bounds and the session cap, cancellation.
- Main: one window per entry, the session bound to its window, a method from another web contents refused, the
  close prompt.
- Renderer (Vitest): languages by extension, find and replace, word count of a selection, the conflict dialog.
- E2E: F4 opens a file, edit, Ctrl+S, the file on disk; a file changed on disk shows the conflict; Shift+F4.

## Benchmarks

`BENCH_STAGE=C10.6`; keystroke to paint ≤ 16 ms at p95 on 1 MB of Markdown; opening 1 MB ≤ 300 ms; a local
save of 1 MB ≤ 150 ms; the viewer's and the commander's bundles unchanged.

## Acceptance criteria

- A README, a JSON config and a 1 MB Markdown file open, color, edit, find and replace and save, keeping their
  encoding and line endings; a conflict never loses either side.
- Nothing in the editor window can name a path or another entry; the viewer cannot open it.

## Risks

- Encoding round trips (a file with mixed line endings; a legacy code page): keep the original bytes' style and
  refuse to save what cannot be encoded, with a choice to save as UTF-8.
- Antivirus and sync tools holding the file during the rename on Windows: retry briefly, then report.

## Results (2026-10-24, Windows, i9-13900K)

**Built.**

- **Window:** an editor window of its own: `app://texteditor/`, its own preload and the `texteditor` profile, matched
  before the apps. The page never names a file: main binds the sidecar's session to the window.
  - Code: `src/shared/doceditor` (CodeMirror 6), main's `textEditorWindow.ts`, the sidecar's `internal/textedit`.
- **Opening:** F4 opens it when Settings names no editor, on every OS. Shift+F4 makes a file and opens it the same
  way. A binary or a file over 8 MB gets a notice that points to F3.
- **Editing:** syntax colours by file type, loaded on first use; colours inside fenced code blocks are left out for
  speed. Also find and replace with a match count, a word count off the keystroke path, soft wrap, and a status bar
  showing line and column, the counts, the encoding, the line endings and the language.
- **Saving:**
  - It keeps the file's encoding (UTF-8 with or without BOM, UTF-16, the eight code pages) and its line endings
    byte for byte.
  - It writes atomically: a partial file in the same folder, fsync, then a rename, with the Windows in-use retry.
    It writes through symlinks; a file with hard links is written in place.
  - A change on disk is a conflict: Overwrite, Reload or Cancel. Text the encoding can't hold offers "Save as UTF-8".
  - Closing with unsaved changes asks Save, Don't save or Cancel.

**Tests.**

- Go: the `textedit` package and the app handlers. Byte-for-byte round trips, conflicts, failed writes, refusals,
  chunk limits, sessions, and the Windows in-use retry.
- Contracts: 220 tests, including the new golden fixtures.
- Main: the window manager, the router profile (an app cannot call the editor's methods; the editor cannot call
  anything else), validators, F4 routing, and the editor's CSP.
- Page: 91 unit tests.
- Commander: the F4 refusals.
- E2E (`specs/commander/texteditor.spec.ts`, 3 of 3 pass):
  - edit and save Markdown;
  - a Windows-1252 CRLF file kept byte for byte;
  - a change on disk → conflict → Overwrite;
  - the close prompt (Cancel, then "Don't save");
  - F4 on a binary;
  - 1 MB opened, typed in, searched and saved.
- `viewers.spec.ts`: its F4 step now expects the editor window, and no program is started. Three older steps of that
  spec fail before reaching F4: the lister at line 75, the program dialog at line 196, and the 2 GB memory
  benchmark. They look like the stale commander specs P04 records, but this was not checked against a clean
  checkout.
