# Stage C10.7 — Markdown Modes (Source, Live, Preview) and Images

Status: **Implementation done** (2026-10-24, Windows; planned 2026-10-23, owner request: in the first release).
Track: commander. Depends on: C10.6. Unblocks: C10.8. Open: the Linux Go run (links), the macOS and Linux app
runs, the NVDA pass; following a link (see Results).

## Objective

Markdown that looks like the finished page while you type, a read-only preview, a switch between them and the
plain text, and pictures dropped or pasted straight into the text.

## Decisions applied

- ADR-0046 (accepted in C10.6): the live view as decorations over the `@lezer/markdown` tree; images in `assets/`
  beside the document; linked images through read-only tokens; nothing loaded from the web; raw HTML as text.

## Scope

- **The mode switch** (owner request 2026-10-23), in the editor's header for Markdown files: **Source** (the C10.6
  text editor), **Live** (below) and **Preview** (the rendered page, read-only; links and task boxes work, nothing
  can be typed). Ctrl+E steps through them. The cursor's line and the scroll position carry over through the
  source lines; undo history, unsaved changes and find and replace are shared by the three (one document). The
  last mode is remembered per file type; Markdown opens in Live at first. Other files show no switch.
- **Preview:** HTML rendered from the lezer tree (the renderer the PDF export prints, built here), cleaned by
  DOMPurify, with the live view's look; long documents render the visible part first.
- **Live view**: headings in their sizes, bold, italic, strikethrough,
  inline code and code blocks with syntax colors, links, block quotes, lists and task lists (a click ticks a box),
  tables, horizontal rules, and images shown inline. The syntax marks hide away from the cursor's line and show on
  it, so editing stays exact; the file's text never changes by itself.
- **Images:** paste a screenshot or drop picture files into the text; each is written under a unique name into
  `assets/` beside the document (Settings → Edit names the folder), and a relative link is inserted where the
  cursor or the drop is. A dropped picture is copied too, never linked where it lies: linking it there would have
  the page hand main a path, which no page may (CLAUDE.md, ADR-0027); identical bytes already in the folder are
  linked instead of copied again (amended 2026-10-24). Linked images resolve in one batched call per visible range.
- Links open in the commander (a local file or folder) or, after a confirmation, in the browser.

## Non-goals

- A WYSIWYG editor that rewrites the Markdown; HTML blocks rendered; math and diagrams; images from the web.

## Implementation tasks

0. The mode switch (a segmented control and Ctrl+E), the position mapping between modes, the per-type memory.
1. Decorations and widgets over the lezer tree for the visible range only; the cursor-line reveal; task boxes.
2. Sidecar: `editor.asset` (chunks of a picture; checks it is a picture by its bytes, ≤ 25 MB; a unique name in the
   assets folder; returns the relative link), `editor.resolveImages` (a batch of relative links → entries inside
   the document's tree, then read tokens from main).
3. The editor window's CSP gains the media protocol for those tokens only.

## APIs/contracts

- Page → main (the `texteditor` profile): `texteditor.assetChunk { seq, data: Uint8Array ≤ 1 MiB }`,
  `texteditor.assetCommit { name }` → `{ link, reused }`, `texteditor.resolveImages { links ≤ 200 }` →
  `{ images: [{ link, src | null }] }` (read-only token URLs for `<img>`, from a token store of their own).
- Main → sidecar: `textedit.assetChunk { sessionId, seq, data (base64) }`, `textedit.assetCommit { sessionId,
  name, folder }`, `textedit.resolveImages { sessionId, links }` → `{ images: [{ link, path | null, type | null }] }`.
  Types by their bytes: PNG, JPEG, GIF, WebP, BMP, AVIF (no SVG); at most 25 MiB.

## Tests

- The switch: each mode from each mode keeps the cursor's line, the scroll position, the undo history and the
  unsaved state; Preview takes no typing; the remembered mode per file type; no switch for a JSON file.
- Preview's HTML for a CommonMark and GFM corpus (golden files); unsafe HTML removed.
- Decorations match the source for a CommonMark and GFM corpus; the cursor line shows the marks; typing in a
  decorated line keeps the text exact.
- Paste and drop: names, the folder, a non-picture refused, a picture outside the tree copied, inside linked.
- E2E: paste a screenshot, the file in `assets/`, the link in the text, the picture shown.

## Benchmarks

`BENCH_STAGE=C10.7`; the C10.6 keystroke budget holds with the live view on a 1 MB document with 200 images.

## Acceptance criteria

- A README with headings, code, tables and pictures reads like the rendered page while it is edited, and saves
  byte for byte as typed.

## Risks

- Decoration cost on very long documents: visible range only, rebuilt incrementally from the tree's changes.

## Results (2026-10-24, Windows, i9-13900K)

**Built.**

- **The three modes** for Markdown files, in the editor's header (a radio group; Ctrl+E steps through them):
  - **Source:** the C10.6 editor.
  - **Live:** the Markdown editor that looks like the page.
  - **Preview:** the rendered page, read-only.
  - All three are one document: undo history, unsaved changes and the cursor's line carry over.
  - The last mode is remembered (Live at first). Other files show no switch.
  - In Preview, Ctrl+F returns to the last editor mode with the find panel open.
- **Live:**
  - Decorations for the visible ranges only: headings, emphasis, code, links, quotes, lists, rules and tables.
  - A task box toggles `[ ]`/`[x]` by editing the text.
  - Pictures are shown under their line.
  - The marks hide away from the cursor's lines and show on them.
- **Preview** (`markdown/html.ts`, a pure serializer over the same lezer tree; C10.8 prints it):
  - Covers CommonMark plus GFM tables, task lists and strikethrough.
  - Raw HTML shows as text. Links are limited to http(s), mailto and relative ones; `javascript:` is removed.
  - The HTML is cleaned by DOMPurify. Pictures only through tokens; web pictures are placeholders.
  - Rendered in sections around the visible line first.
- **Pictures:** paste and drop send the bytes in 1 MiB chunks, in order. The sidecar:
  - checks the type by the bytes (PNG, JPEG, GIF, WebP, BMP, AVIF; no SVG);
  - writes the picture into the folder beside the document under a unique name, without overwriting;
  - reuses an identical file already there.
  The link goes where the cursor or the drop was.
- **Linked pictures:** resolved in batches of up to 200, inside the document's folder tree only (also after
  following links). Shown through a token store of their own.
- **Settings → Editor and tools → Pictures folder:** one plain name; empty means `assets`.
- **Found on the way (ADR-0046):** quitting with unsaved text had stopped the sidecar before the editor asked, so
  Save could not be written. Quitting now asks first and stops nothing while a window asks.

**Tests.**

- Go:
  - each picture type, refused types, chunk order and limits;
  - unique names and reuse, bad folder names, no partial file left;
  - resolving relative, escaping, absolute, scheme and link forms; the 200 cap;
  - golden fixtures (contracts: 220 tests).
- Main: the picture calls, tokens instead of paths, the CSP (`img-src` token pictures only), and the quit asking
  only dirty windows.
- Page: 158 unit tests. They cover the serializer's golden cases (unsafe HTML and links), the Live decorations, the
  mode switch, paste and drop, and the resolver's batches.
- E2E (`specs/commander/texteditor.spec.ts`, 6 of 6 pass with C10.6's):
  - Live, Preview and Source on one document, with the task box, the picture through a token, raw HTML inert and
    `javascript:` removed;
  - a pasted picture reused when identical, else written into `assets/`;
  - quitting with unsaved text: the window asks, Save writes, then the app quits.

**Left for later:**

- Following a link: Ctrl+click shows its target; opening it, in the commander or in the browser after a
  confirmation, needs a main method.
- Relative `.md` links are not followed.
- Colours inside fenced code blocks stay off: they raised the keystroke p95 on code-heavy 1 MB documents.
