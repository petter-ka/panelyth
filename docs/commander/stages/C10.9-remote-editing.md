# Stage C10.9 — Editing Files on Servers

Status: **Planned** (2026-10-23, owner request: in the first release). Track: commander. Depends on: C10.6,
C10.5 (FTP connections, ADR-0037). Unblocks: C11.

## Objective

Open a file on an FTP or FTPS server in the editor and save it back to the server.

## Decisions applied

- ADR-0046 and an amendment to ADR-0037 (decided here): a remote file can be edited; saving writes the cached copy
  and uploads it to a temporary name on the server, then renames it over the file, so a broken upload never
  truncates it; the conflict check compares the server's modified time and size. SFTP stays out of scope.

## Scope

- F4 on a file in a server panel downloads it (a queue job with progress for large files) and opens it in the
  editor; the title says which server.
- Ctrl+S saves the cached copy and uploads it as one job; the status bar shows "Uploading…" and then "Saved to
  server"; a failed upload keeps the changes in the editor and offers Retry.
- A file changed on the server since it was opened is a conflict, as for local files (Compare downloads the
  server's copy into the diff).
- The editor holds its connection while it is open; a dropped connection reconnects with the saved connection's
  credentials or asks.
- A server that cannot rename (some FTP servers refuse RNFR/RNTO over an existing file) falls back to delete and
  rename after a confirmation.

## Non-goals

- SFTP, WebDAV and cloud storage; editing files inside archives on a server; collaborative editing.

## Implementation tasks

1. ADR-0037 amended. Sidecar: the editor session over a remote entry (download, the cached copy, the version from
   the listing), the upload to a temporary name and the rename, the conflict from a fresh listing of that entry.
2. Main and renderer: the server in the title, upload states in the status bar, retry.

## APIs/contracts

- The C10.6 methods unchanged; `editor.session` gains `{ remote: { host, path } | null }`; `editor.state` gains
  `uploading` and `uploadFailed`.

## Tests

- Go against the test FTP server (ADR-0037's harness): edit and save, the temporary name and rename, a broken
  upload leaves the server's file whole, the conflict, a server without rename over an existing file, reconnect.
- E2E: open a file on the test server, edit, save, the server's file changed.

## Benchmarks

`BENCH_STAGE=C10.9`; saving 1 MB to the local test server ≤ 1 s; the editor stays responsive while it uploads.

## Acceptance criteria

- A config file on an FTP server is edited and saved back; a cut connection during the upload never damages it.

## Risks

- Servers with coarse modified times (whole minutes): the size and a hash of the downloaded copy back the check.
