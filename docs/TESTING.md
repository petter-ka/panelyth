# Testing Strategy

## Unit tests

### React

Test:

- virtual range -> visible items
- page loading
- infinite scroll threshold
- keyboard navigation
- selection
- error placeholders
- theme state (dark default, cycling, persistence)
- design tokens: neutral grays and WCAG AA contrast, parsed from the real CSS (`src/styles/tokens.test.ts`)

### Go

Test:

- path normalization
- image type detection
- source identity
- cache key generation
- cache hit/miss
- request coalescing
- cancellation
- scanner filtering
- SQLite queries
- atomic cache write behavior

## Integration tests

### Go

- scan a generated fixture tree
- index many images
- query deterministic pages
- generate thumbnails
- reopen and hit cache

### Electron

- start sidecar
- open folder
- fetch first page
- request visible previews
- shutdown/restart sidecar cleanly

## End-to-end

Scenarios:

1. open folder with 100 images
2. open folder with 10k images
3. open folder with 100k synthetic files
4. scroll continuously
5. change tile size
6. revisit same folder
7. replace an image in place
8. cancel an in-progress scan
9. permission/error case
10. restart application after cache exists

### Layout in jsdom

jsdom has no layout. Renderer tests that mount the tile view call `mockViewport(width, height)` (`src/test/viewport.ts`),
which fakes `getBoundingClientRect` (read by the tile view) and `offsetWidth`/`offsetHeight` (read by TanStack Virtual).
Real geometry, scrolling and frame timing are covered by the Electron e2e tests (`tests/e2e/specs/tiles.spec.ts`).

### Isolation

Every Electron launch in e2e and benchmarks gets fresh `FASTVIEW_CACHE_DIR`, `FASTVIEW_CONFIG_DIR` and
`FASTVIEW_USER_DATA_DIR` directories, so stored preferences, caches and logs never leak between runs. The
profile override is honoured only in unpackaged builds. `FASTVIEW_TEST_SHELL=record` (set by `launchApp`) makes main
record "open with default app", "show in file manager" and clipboard writes in `__fastviewShellLog` instead of
performing them.

Radix triggers in jsdom: with `mockViewport` every element has the same rectangle, so react-resizable-panels treats
each pointerdown as a divider drag and prevents it. App-shell tests open dropdowns from the keyboard and type into
already focused inputs (`skipClick`). Pointer behavior is covered by the Electron e2e tests.

## Performance fixtures

Generated by `native/fastview-go/cmd/fixturegen` (shared by Go tests, `pnpm bench:index` and e2e), cached per machine
under `<tmp>/fastview-fixtures/<name>` with a marker file: `flat-100k` (90k media + 10k non-media), `tree-50k`
(depth 3 × fanout 6, 46,620 media), `flat-5k`, and real images: `images-150` (1600×1200, PNG-with-alpha and
EXIF-rotated variants; e2e) and `images-12mp-120` (4000×3000; `pnpm bench:previews`, viewer e2e), `images-48mp-3` (8000×6000; large-decode e2e), `tree-small` (navigation e2e) and `subdirs-10k` (a folder with 10,000
subfolders for the lazy tree; created by the e2e spec). Mtimes are fixed, so query
results are deterministic.

Keep deterministic fixture sets for:

- small folder
- large folder
- huge folder
- mixed unsupported files
- repeated filenames
- rapidly changing files

## Benchmarks

Track:

- files/sec scan
- metadata/sec
- SQLite page latency
- JPEG decode + resize latency
- cache hit latency
- cache miss end-to-end latency
- renderer frame/scroll behavior

Do not rely only on synthetic microbenchmarks. Include a real end-to-end benchmark path.
